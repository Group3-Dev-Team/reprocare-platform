# Deployment configuration

The canonical project is [Group3-Dev-Team/reprocare-new](https://github.com/Group3-Dev-Team/reprocare-new).

- **FastAPI service** uses `DATABASE_URL` for PostgreSQL, `APP_ENV=production`, `ALLOW_DEMO_ACCOUNTS=false`, and `CORS_ORIGINS` set to the exact HTTPS frontend origin or comma-separated origins. Store the database URI, optional bot HTTP `IMPORT_API_KEY`, and optional `GOOGLE_PLACES_API_KEY` in the host’s private environment or secret store. `GOOGLE_PLACES_LIVE_DAILY_LIMIT` caps live searches, listings and review requests per day (default 200); `GOOGLE_PLACES_PHOTO_DAILY_LIMIT` caps Google photos (default 0, off). `SESSION_DAYS` controls token lifetime. Supabase can provide PostgreSQL while ReproCare handles application authentication.
- **React build** uses `VITE_API_URL` set to the public HTTPS FastAPI origin, without `/api` at the end. Keep `VITE_DEMO_MODE=false` for the connected application. Serve the build’s `dist/` directory and configure the static host to serve `index.html` for client-side routes. The Leaflet directory map uses OpenStreetMap tiles. An optional `VITE_GOOGLE_MAPS_BROWSER_KEY` is visible in the browser and should be restricted by HTTP referrer and API.
- **Private bot runner** uses the database URI for direct imports or a server-side `IMPORT_API_KEY` for authenticated HTTP imports. `GOOGLE_PLACES_API_KEY` enables Places lookup, and `APIFY_API_TOKEN` enables TikTok collection. Facebook uses a Playwright browser profile with a manually signed-in session. Keep `REPROCARE_BOT_HOME`, browser profiles, staged feedback and caches outside the Git checkout. The bot can run independently of the web services.
- **Database releases** should use a private backup and a rehearsal on a separate database before applying reviewed additive migrations. For an already configured database, verify schema and connectivity first. The application retains collected feedback, and Facebook data remains subject to the review queue. Do not run test resets, fixture seeds or purge commands against the application database.
- **Configuration check**: from `backend/`, run `python -m app.check_config` before migrating. It reports which variables are set or missing, tests the database connection and never prints secret values; it exits with status 1 when a required setting is missing or the database cannot be reached.
- **Migrations** in `backend/migrations/versions/` are additive and applied in name order by `python -m app.database.migrate`:
  `0001`–`0003` (public feedback tables and Facebook moderation), `0004` (password recovery), `0005` (Google sign-in) and `0006` (one pending appointment request per patient, facility and date). Before `0006`, check for existing duplicate pending requests with the query in the migration file. Fresh databases created by `init_db` already include the index.
- **Optional integrations** stay disabled until configured: password recovery (`PASSWORD_RESET_*` settings, migration `0004`; on hosts that block SMTP ports, such as free Render web services, set `PASSWORD_RESET_DELIVERY=brevo` or `resend` with `PASSWORD_RESET_API_KEY` and a verified `PASSWORD_RESET_SMTP_FROM`), Google sign-in (`GOOGLE_OAUTH_*`, migration `0005`), facility photo uploads (`CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`; the backend signs each upload and the secret never reaches the browser) and the WhatsApp support link (`VITE_WHATSAPP_SUPPORT_NUMBER`, only with an approved public number). Displaying uploaded photos on listings additionally needs a stored photo field, which is not part of the current schema. Google Maps photos are shown live (not stored) for facilities with a linked Place ID when the photo limit is above 0.
- **Bot imports into the hosted database**: set `IMPORT_API_KEY` (a long random value) on the backend service and the same value in the bot's environment. The bot then sends staged batches with `reprocare_bot.py import --api https://<backend>`; facilities are matched by Google Place ID, and the bot needs no database credentials. `FACEBOOK_AUTO_SCREENING=true` publishes relevant comments from a facility's own linked Facebook page automatically, holds personal health details, allegations and uncertain comments for an administrator, and hides the rest; posts from other pages always wait for moderation.
- **Search indexing**: set `VITE_PUBLIC_SITE_URL` to the public HTTPS origin at build time to emit an indexable `robots.txt` and `sitemap.xml`. Without it the build disallows all crawling. Dashboards, authentication callbacks, password reset and API paths are always excluded.
- Keep `backend/.env` and any frontend local overrides private. The checked-in examples contain names and placeholders. Run backend and browser-bot tests using dedicated disposable PostgreSQL databases.
